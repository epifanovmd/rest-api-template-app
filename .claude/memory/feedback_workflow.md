description: Задачи разбивать на анализ → план → мелкие итерации → проверка; багфикс через падающий тест; только стрелочные функции
type: feedback
---

Всегда разбивать задачи на этапы: анализ → подробный план → поэтапное выполнение мелкими итерациями.

**Why:** Пользователь хочет контролировать процесс, видеть план до начала работы, и получать стабильный код после каждого шага.

**How to apply:**

1. Сначала прочитать все затронутые файлы, понять scope
2. Войти в plan mode, составить пошаговый план с конкретными файлами
3. Показать план, дождаться подтверждения
4. Выполнять по одной итерации, каждая — рабочее состояние
5. После каждой итерации — lint/build проверка
6. Сообщать прогресс между итерациями

**Дополнительно (23.09.2026):**

- Багфикс — сначала тест, воспроизводящий баг и падающий на текущем коде, затем правка, затем зелёный прогон; тест остаётся.
- Все функции — стрелочные; `function`-объявления запрещены (проверяется `func-style: expression` в `eslint.config.mjs`). Методы классов — методы.
- Ветки: правка общего кода — в `main`, затем merge в ветки-примеры (`example/*`); в ветке-примере правится только
  код её модулей. Базовую миграцию main не пересоздавать — только новые миграции.
- Корневые документы (`ARCHITECTURE.md`, `MODULE-CHEATSHEET.md`, `CONVENTIONS.md`, `CLEAN-CODE.md`, `DESIGN-PRINCIPLES.md`, `README.md`) меняются только в исключительных случаях — при смене архитектуры/принципов/паттернов; память `.claude/memory/` обновляется свободно.
