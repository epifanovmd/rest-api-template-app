# Багфикс

Правила — [process/bugfix](../../../docs/10-process/bugfix.md), общий цикл —
[process/workflow](../../../docs/10-process/workflow.md).

1. **Воспроизвести**: шаги, ожидаемое, фактическое. Не воспроизводится — собрать
   данные или спросить, не угадывать.
2. **Причина**: найти корень, а не место проявления; проверить соседние места с тем
   же паттерном.
3. **План** с первой итерацией «падающий тест» → показать пользователю → ждать
   подтверждения. Ветка `fix/…` по [process/git](../../../docs/10-process/git.md#ветки).
4. **Тест**: написать (можно субагентом `tester`), запустить, убедиться, что падает
   именно из-за бага. Сохранить вывод падения.
5. **Исправление** — минимальное, по причине, без попутного рефакторинга.
6. **Зелёный прогон**: новый тест, затем полная проверка
   ([ops/commands](../../../docs/70-ops/commands.md)).
7. README модуля: gotcha, если причина неочевидна. Тест не удалять.
8. **Отчёт**: причина; тест и вывод падения до исправления; что изменено; соседние
   места.

Тест невозможен (рантайм или окружение недоступны в тестах, внешняя гонка) — сообщить до исправления и
описать ручное воспроизведение.

Баг: $ARGUMENTS
