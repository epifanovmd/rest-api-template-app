# Задача разработки

Правила этапов — [process/workflow](../../../docs/10-process/workflow.md). Порядок:

1. **Приём.** Сформулировать результат. Неоднозначно — спросить и остановиться.
2. **Анализ.** [docs/modules.md](../../../docs/modules.md) → README затрагиваемых
   модулей; документы из [индекса](../../../docs/README.md) по этапам `analysis`,
   `planning`; место кода — [placement](../../../docs/20-architecture/placement.md).
   Крупная или межслойная задача — субагент `architect` для независимого плана.
3. **План.** Итерации с файлами и проверками → показать пользователю → **ждать
   подтверждения**. До него код не меняется. Создать ветку по [process/git](../../../docs/10-process/git.md#ветки).
4. **Итерации.** По одной; после каждой — быстрая проверка и тесты области
   ([ops/commands](../../../docs/70-ops/commands.md)). Красное — чинить до перехода дальше. Сообщать прогресс.
5. **Проверка.** Полная проверка проекта, `git diff --check`; вывод — в отчёт.
6. **Ревью.** `/review` по своему diff.
7. **Документация.** README изменённых модулей; повторяющееся без правила —
   `/propose-rule`.
8. **Итог.** Сделано; проверки с цифрами; что не проверено; предложения в inbox;
   замеченное вне scope. Коммит — только по команде (`/commit`).
