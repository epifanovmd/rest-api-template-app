# Как добавить документ

## Куда класть

| Знание                                         | Место                                                    |
| ---------------------------------------------- | -------------------------------------------------------- |
| как работает сама система документации         | `docs/00-meta/`                                          |
| этап, процедура, git, проверки                 | `docs/10-process/`                                       |
| слой, граница, общий механизм без имён модулей | `docs/20-architecture/`                                  |
| почему принято архитектурное решение           | `docs/20-architecture/adr/`                              |
| как писать код (оформление, именование)        | `docs/30-conventions/`                                   |
| общий принцип проектирования                   | `docs/40-principles/`                                    |
| сквозная техническая справка проекта           | `docs/50-tech/`                                          |
| предметная область, сценарии, бизнес-правила   | `docs/60-domain/`                                        |
| окружение, сборка, деплой                      | `docs/70-ops/`                                           |
| устройство одного модуля, его gotcha           | `src/<путь модуля>/README.md`                            |
| автоподгрузка правил при работе с файлами      | `.claude/rules/<тема>.md` с `paths`                      |
| многошаговая процедура, вызываемая командой    | `.claude/skills/<имя>/SKILL.md`                          |
| роль для делегирования                         | `.claude/agents/<роль>.md`                               |
| правило, которое можно проверить машиной       | линтер, git-хук или `scripts/` — плюс строка в документе |

Одно правило — в одном месте. Остальные места ссылаются на него, а не пересказывают.
Исключение — выжимки в `CLAUDE.md` и `.claude/rules`: одна строка со ссылкой на
источник.

## Формат документа `docs/`

Шаблон — [templates/doc.md](templates/doc.md). Frontmatter обязателен:

| Поле         | Значение                                                                                              |
| ------------ | ----------------------------------------------------------------------------------------------------- |
| `id`         | путь от `docs/` без номера папки и `.md`: `process/bugfix`                                            |
| `title`      | заголовок                                                                                             |
| `summary`    | одна строка — попадает в индекс; по ней решают, читать ли документ                                    |
| `layer`      | `core` / `stack` / `project`                                                                          |
| `roles`      | `all`, `developer`, `architect`, `tester`, `reviewer`, `devops`, `documenter`                         |
| `stages`     | `any`, `intake`, `analysis`, `planning`, `implementation`, `verification`, `review`, `docs`, `commit` |
| `depends_on` | id документов, которые надо знать раньше; граф без циклов                                             |

## Формат README модуля

Шаблон — [templates/module-readme.md](templates/module-readme.md). Frontmatter:
`module` (путь от `src/`) и `summary` — то же описание стоит в строке карты
`docs/modules.md`. Содержимое — назначение, public API, устройство, зависимости,
gotcha. Не пересказывать код и общие правила.

## Размер и стиль

- Документ — одна тема, до ~150 строк. Больше — делить по подтемам.
- `CLAUDE.md` — до 150 строк.
- Текст по фактам, без истории изменений («раньше было…», даты правок).
- Ссылки — относительные markdown-ссылки на существующие файлы.

## Индекс

Индексы ведутся вручную, в той же правке, что и документ:

- добавлен, переименован или удалён документ `docs/**` — строка в таблице его папки
  в [docs/README.md](../README.md): ссылка `id`, `summary`, слой, роли, этапы;
- добавлен, переименован или удалён README модуля — строка в
  [docs/modules.md](../modules.md): ссылка, `summary`;
- изменился `summary` — он же обновляется в строке индекса.

Перед завершением правки сверить: frontmatter заполнен, `id` совпадает с путём,
ссылки ведут на существующие файлы, `depends_on` ссылается на существующие `id`.
