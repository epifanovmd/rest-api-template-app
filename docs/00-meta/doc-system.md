# Устройство системы знаний

Вся документация, правила и процедуры проекта собраны в одной системе. Её задача —
дать агенту (и человеку) ровно то знание, которое нужно для текущего шага, не
загружая остальное.

## Уровни

| Уровень | Где                                        | Когда загружается                              | Что содержит                                                    |
| ------- | ------------------------------------------ | ---------------------------------------------- | --------------------------------------------------------------- |
| L0      | `CLAUDE.md`                                | всегда                                         | точка входа: карта, инварианты, этапы кратко, протокол защиты   |
| L1      | `.claude/rules/*.md` (frontmatter `paths`) | автоматически при чтении/правке файла по маске | выжимка правил области + ссылки на источник истины              |
| L2      | `docs/**`                                  | по ссылке, когда нужен                         | полная документация: одна тема — один файл                      |
| L2      | `src/**/README.md`                         | по правилу L1 при работе в модуле              | документация модуля рядом с кодом                               |
| L3      | `.claude/skills/<name>/SKILL.md`           | описание — всегда, тело — при вызове           | процедуры этапов: задача, багфикс, коммит, ревью, правка правил |
| L4      | `.claude/agents/*.md`                      | при делегировании                              | роли-субагенты: архитектор, ревьюер, тестировщик, документатор  |
| L5      | линтеры, git-хуки, `scripts/`              | исполняются машиной                            | границы слоёв, формат коммитов, индекс документов               |

Принцип: **правило, которое можно проверить машиной, проверяется машиной (L5)**.
Текст объясняет причину, автоматика не даёт нарушить. Правила, которые машина
проверить не может (например, защита документов), соблюдаются по тексту.

Скрипты `scripts/docs` от проекта не зависят: карта модулей собирается из всех
`src/**/README.md`.

## Карта `docs/`

| Папка              | Содержимое                                              | Слой    |
| ------------------ | ------------------------------------------------------- | ------- |
| `00-meta/`         | устройство системы, приоритеты, защита, шаблоны         | core    |
| `10-process/`      | этапы разработки, багфикс, git, проверки, ревью, роли   | core    |
| `20-architecture/` | слои, границы, public API, состояние, DI, ошибки, ADR   | stack   |
| `30-conventions/`  | как писать код: имена, импорты, типы, ошибки, тесты     | stack   |
| `40-principles/`   | clean code, SOLID, паттерны                             | core    |
| `50-tech/`         | техническая справка проекта: устройство, рецепты, тесты | project |
| `60-domain/`       | предметная область: продукт, глоссарий, сценарии        | project |
| `70-ops/`          | окружение, команды, сборка, деплой, git-хуки            | project |
| `inbox/`           | предложения новых правил, ждут решения пользователя     | —       |

Номер папки — приоритет при конфликте ([priority](priority.md)).

Сгенерированные индексы:

- [docs/README.md](../README.md) — все документы с описанием, по ролям и этапам;
- [docs/modules.md](../modules.md) — все документы модулей `src/**/README.md`.

## Общее и частное

- `00`–`40` описывают принципы, архитектуру и правила **без проектной конкретики**
  (имён модулей, классов, файлов) — так они переносимы в другие проекты.
- `50`–`70` и README модулей — **конкретика проекта**: имена, файлы, gotcha.
- Факт об одном модуле живёт в README модуля, а не в `docs/`.
- Документ `20`/`30` может закончиться ссылкой «реализация в проекте — README
  модуля»: это навигация, а не проектная конкретика в тексте правила.

## Как искать

1. Вопрос «что за правило / как принято» → индекс [docs/README.md](../README.md).
2. Вопрос «как устроен модуль X» → [docs/modules.md](../modules.md) → README модуля.
3. Вопрос «где код X» → `Grep`/`Glob` по `src/`, затем README найденного модуля.
4. Ответа нет нигде → ситуация не описана: действовать по
   [protection](protection.md#предложение-правил) — предложить правило.
