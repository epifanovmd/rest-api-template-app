# Приоритеты и разрешение конфликтов

## Старшинство источников

От старшего к младшему:

1. Прямое указание пользователя в текущей задаче.
2. Автоматические проверки (L5): линтер, typecheck, тесты, git-хуки. Фактическое поведение
   определяет конфигурация; расхождение текста с ней устраняется отдельно.
3. `CLAUDE.md`.
4. `docs/` по номеру папки: `00-meta` > `10-process` > `20-architecture` >
   `30-conventions` > `40-principles` > `50-tech` > `60-domain` > `70-ops`.
5. README модуля.
6. Существующий код. Код — пример, только если он соответствует правилам выше;
   legacy-отклонения образцом не являются.

Правило `.claude/rules` — выжимка документа, а не отдельный источник: при расхождении
прав документ, на который правило ссылается.

## Противоречие

Если два источника противоречат друг другу или правило не покрывает ситуацию:

- не выбирать вариант самостоятельно и не придумывать новое архитектурное решение;
- остановиться, описать противоречие пользователю с ссылками на оба места;
- предложить решение и, если ситуация может повториться, — запись в
  [inbox](protection.md#предложение-правил).

## Слои документов

Каждый документ размечен полем `layer`:

| Слой      | Что                                                                 |
| --------- | ------------------------------------------------------------------- |
| `core`    | процесс, git, clean code, сама система документации                 |
| `stack`   | архитектура и конвенции стека (архитектурный стиль, фреймворки, DI) |
| `project` | конкретика проекта: модули, домен, окружение                        |
