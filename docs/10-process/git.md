# Работа с git

## Что требует команды пользователя

Без явной команды не выполняются: commit, push, merge, rebase, reset, amend,
force-push, удаление веток, `git clean`, `git checkout -- <файл>` поверх чужих
изменений. Разрешение на одно действие не распространяется на следующее.

## Ветки

- Задача — отдельная ветка от актуального `main`: `<type>/<kebab-описание>`, где
  `type` — как у коммита: `feat/<модуль>-<что>`, `fix/<модуль>-<что>`.
- Создать ветку агент может сам на этапе выполнения — это обратимо.
- В основную ветку попадает только то, что прошло полную проверку
  ([ops/commands](../70-ops/commands.md)).

## Коммиты — Conventional Commits

```
<type>(<scope>)!: <описание>

<тело: что и почему, по пунктам при необходимости>
```

| Поле      | Правило                                                                                    |
| --------- | ------------------------------------------------------------------------------------------ |
| `type`    | `feat` `fix` `refactor` `perf` `test` `docs` `style` `build` `ci` `chore` `revert`         |
| `scope`   | имя модуля, для документации — `docs`                                                      |
| `!`       | ломающее изменение: удалён или изменён public API, маршрут, экран или эндпоинт, контракт   |
| описание  | на русском, со строчной буквы, без точки в конце; что изменилось для пользователя или кода |
| заголовок | до 100 символов; подробности — в теле через пустую строку                                  |

- Один коммит — одно логическое изменение. Форматирование и рефакторинг не
  смешиваются с поведением.
- Перегенерированный код (клиент API, маршруты, спецификация) — в коммите той фичи,
  ради которой он изменился, с пометкой в теле.
- Merge, revert, `fixup!`/`squash!` — в стандартном формате git, правила выше на них
  не распространяются.

## Перед коммитом

- `git status` и `git diff` просмотрены: в коммит попадает только задача.
- Не коммитятся: секреты, локальные настройки, отчёты покрытия и артефакты сборки;
  какие env-файлы хранятся в git — [ops/environment](../70-ops/environment.md).
- Git-хуки не обходятся (`--no-verify` запрещён без команды пользователя).
