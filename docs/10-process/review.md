# Ревью изменений

Ревью — сверка diff с правилами, а не пересказ изменений. Каждое замечание
ссылается на правило (документ и раздел) и место в коде.

## Когда

- Всегда — самопроверка своего diff перед итогом.
- Субагент `reviewer` — изменения в нескольких слоях, в общей инфраструктуре, в публичных
  контрактах, или по просьбе пользователя. Ему передаётся diff и список задач, а не
  собственные выводы.

## Чек-лист

Общие пункты — здесь, пункты стека — [conventions/checklist](../30-conventions/checklist.md).

**Архитектура** — [placement](../20-architecture/placement.md),
[dependencies](../20-architecture/dependencies.md)

- [ ] Код в модуле-владельце; ничего не изобретено вне правил.
- [ ] Архитектурные границы не нарушены; внешние импорты — через public API модуля.
- [ ] Public API не раскрывает лишнего.

**Код** — [conventions](../30-conventions/naming.md),
[clean-code](../40-principles/clean-code.md)

- [ ] Имена файлов и директорий по соглашению.
- [ ] Функции стрелочные; хелперы выше использования.
- [ ] Нет новых отключений линтера без причины рядом.
- [ ] Подписки, таймеры, ресурсы освобождаются; учтены устаревшие и повторные вызовы.
- [ ] Нет абстракций без текущей потребности.
- [ ] Неиспользуемый существующий код не удалён без команды пользователя.

**Тесты** — [conventions/tests](../30-conventions/tests.md)

- [ ] Багфикс — тест, падавший до исправления.
- [ ] Тесты проверяют поведение, не реализацию.
- [ ] Зоны с порогом покрытия (если есть) покрыты.

**Документация** — [protection](../00-meta/protection.md)

- [ ] README модулей актуальны.
- [ ] Защищённые документы не изменены без команды; предложения — в inbox.

## Результат

Список замечаний по убыванию важности: блокирующие (нарушение правила, баг),
желательные, вопросы. Пустой список — тоже результат.
