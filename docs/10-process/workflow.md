# Этапы разработки

Любая задача — фича, багфикс, рефакторинг, правка конфигурации — проходит этапы по
порядку. Этап не пропускается; вопрос пользователю — нормальный исход любого этапа.

## 0. Приём

- Сформулировать ожидаемый результат одной-двумя фразами.
- Неоднозначность, влияющая на результат, — вопрос пользователю до анализа.
- Тип задачи: фича / багфикс ([bugfix](bugfix.md)) / рефакторинг / документация
  (только по явному указанию пользователя, [protection](../00-meta/protection.md)).

## 1. Анализ

- Найти затрагиваемые модули: [docs/modules.md](../modules.md), `Grep`/`Glob`.
- Прочитать README затрагиваемых модулей и документы из индекса по роли и этапу.
- Определить место нового кода по
  [architecture/placement](../20-architecture/placement.md) — не придумывать.
- Выявить риски: границы слоёв, зоны с порогом покрытия (если есть), сгенерированный код, схема данных, права,
  реалтайм, конкурентность (параллельные экземпляры и вызовы, фоновые процессы).

## 2. План — gate

- Пошаговый план: итерации, у каждой — файлы и проверка. Каждая итерация оставляет
  проект в рабочем состоянии.
- Для багфикса первая итерация — падающий тест.
- Показать план пользователю и **дождаться подтверждения**. Без подтверждения код
  не меняется.
- Отклонение от плана в ходе работы — сообщить и согласовать заново.

## 3. Выполнение

- По одной итерации; после каждой — быстрые проверки ([verification](verification.md#после-итерации)).
- Не переходить к следующей, пока текущая не зелёная.
- Сообщать прогресс: что сделано, что дальше.
- Не расширять scope попутно. Замеченное вне задачи — в итоговый отчёт.

## 4. Проверка

- Полная проверка ([verification](verification.md#перед-сдачей)).
- Живая проверка — если для неё есть стенд, e2e, симулятор или устройство
  (`docs/70-ops/`); если нет — прямо сказать.

## 5. Ревью

- Самопроверка diff по [review](review.md); для крупных изменений — субагент
  `reviewer`.

## 6. Документация

- Обновить README изменённых модулей; у нового модуля — создать.
- Изменился факт в защищённом документе или появилась повторяющаяся ситуация —
  предложение в `docs/inbox/` ([protection](../00-meta/protection.md#предложение-правил)).

## 7. Итог и коммит

- Краткое резюме: что сделано, результаты проверок (с цифрами), что не проверено,
  предложения в inbox, замеченное вне scope.
- Коммит и push — только по команде пользователя ([git](git.md)).
