# ADR-0001: система знаний проекта

- Статус: принято; скрипты системы знаний (индекс, проверки документов, формат коммитов) отменены — правила соблюдаются по тексту, индексы ведутся вручную
- Дата: 2026-11-02

## Контекст

Правила жили в шести больших корневых документах и в отдельной проектной памяти агента.
Между ними не было приоритетов и связей, нужное правило приходилось искать чтением
сотен строк, правила области не подгружались автоматически, документации модулей не
было.

## Решение

- Уровни L0–L5 ([meta/doc-system](../../00-meta/doc-system.md)): `CLAUDE.md` →
  `.claude/rules` с `paths` → `docs/` и README модулей → skills → субагенты →
  автоматика.
- Мелкие документы с frontmatter (`id`, `layer`, `roles`, `stages`, `depends_on`),
  сгенерированный индекс, проверка `yarn docs:check` в полной проверке; параметры
  проекта — `docs/config.mjs`.
- Документация модуля — `README.md` рядом с кодом; проектная конкретика из памяти
  агента перенесена туда и в `docs/50–70`, память упразднена.
- Правила и документы меняются только по явному указанию пользователя; новые правила —
  через `docs/inbox/` ([meta/protection](../../00-meta/protection.md)).
- Коммиты — Conventional Commits на русском с проверкой хуком `commit-msg`.

## Альтернативы

- `@import` документов в `CLAUDE.md` — загружает всё сразу, токены не экономит.
- `CLAUDE.md` в каждом модуле — неудобен людям и другим инструментам; вместо этого
  правило L1 направляет к README.
- Хук, блокирующий запись в защищённые пути, — давал ложные срабатывания на путях в
  командах и именах веток; защита оставлена текстовым правилом.

## Последствия

- Постоянно загружены только `CLAUDE.md`, описания skills и сработавшие правила.
- Общий слой (`00`, `10`, `40`, skills, агенты, скрипты) одинаков в проектах, проектные
  параметры — в `docs/config.mjs` и `70-ops/commands`.
- Новые модули обязаны иметь README — это проверяет `docs:check`.
