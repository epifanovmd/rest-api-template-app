# Архитектурные решения (ADR)

ADR фиксирует **почему** принято решение: контекст, альтернативы, последствия.
Правила, вытекающие из решения, живут в профильных документах и ссылаются на ADR.

## Когда писать

- выбор между несколькими разумными архитектурными вариантами;
- новое исключение из общего правила;
- смена библиотеки, механизма или паттерна, затрагивающая несколько модулей.

ADR не переписывается: устаревшее решение получает статус «заменено ADR-XXXX», новое
пишется отдельным файлом. Шаблон — [templates/adr.md](../../00-meta/templates/adr.md),
имя — `<NNNN>-<slug>.md`.
