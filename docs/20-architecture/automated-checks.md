# Автоматические проверки и исключения

Архитектурные правила машинно проверяемы везде, где это возможно.

| Область             | Что проверяется                                                                                                   |
| ------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Маршруты и контракт | генерация проходит, спецификация и маршруты закоммичены актуальными                                               |
| Границы ядра        | ядро, `common` и глобальные типы не импортируют модули (архитектурный тест)                                       |
| Границы модулей     | чужой модуль импортируется через его `index.ts` или файл сущности (архитектурный тест)                            |
| Сущности            | каждая сущность зарегистрирована в модуле                                                                         |
| Импорты             | порядок и группировка импортов и экспортов                                                                        |
| Форматирование      | стиль кода, стрелочные функции, пустые строки между блоками, prettier (pre-commit)                                |
| Типы и юнит-тесты   | typecheck без ошибок, зелёные тесты                                                                               |
| Миграции            | применяются на чистую БД, сущности не расходятся со схемой                                                        |
| Интеграция          | e2e против настоящего сервера и зависимостей, для каждого драйвера хранилища; вызван каждый эндпоинт спецификации |
| Зависимости и образ | аудит production-зависимостей, сканирование образов на уязвимости                                                 |
| Конфигурация        | схема окружения валидируется при старте                                                                           |

Миграции на чистой БД и дрейф схемы, e2e для каждого драйвера хранилища, аудит
зависимостей и уязвимости образов дополнительно проверяет CI. Команды —
[ops/commands](../70-ops/commands.md), порядок проверок —
[process/verification](../10-process/verification.md).

Правило, которое нельзя проверить автоматически (направление связей между модулями, тонкие
контроллеры, события после транзакции), — предмет ревью и описано в
`docs/30-conventions` ([checklist](../30-conventions/checklist.md)).

## Проектные исключения

Исключения из общих правил (файлы, которыми владеет генератор маршрутов или ORM;
точки интеграции с фреймворком, где инъекция невозможна; сгенерированные миграции)
фиксируются в конфигурации инструментов и в документации рядом с ними. Исключение:

1. вызвано требованием фреймворка, генератора, ORM или подтверждённым техническим
   ограничением;
2. максимально узкое;
3. задокументировано рядом с настройкой;
4. не распространяется на новый код автоматически.
