# Конфигурация

- Переменные окружения читаются из файла по имени окружения и валидируются схемой при
  старте. Невалидная конфигурация — немедленное падение с понятной ошибкой, а не
  сюрприз в рантайме. Небезопасная production-конфигурация (пустой пароль БД, CORS
  `*`, нет Redis, неполные ключи хранилища) — ошибка запуска.
- Код получает конфигурацию из типизированного объекта, а не из `process.env`.
  Общие настройки платформы — в едином конфиге; настройки модуля — схема рядом с
  модулем через общий хелпер (те же правила разбора и падения при старте). Модуль
  подключается и удаляется вместе со своими настройками.
- Секреты не попадают в репозиторий; шаблон файла окружения с описанием переменных —
  попадает.
- Флаги окружения (`isProduction`, `isDevelopment`) — единственный способ ветвить
  поведение по среде; строковые сравнения по месту запрещены. Ветвление по роли
  процесса — через конфигурацию роли ([lifecycle](lifecycle.md#роли-процесса)).
- Необязательные интеграции (почта, push, трекер ошибок) выключаются пустой
  переменной. Отсутствие обязательной для операции интеграции в production — 503,
  вне production — безопасная заглушка (например, письмо в лог).

Как добавить переменную — [conventions/config](../30-conventions/config.md).
