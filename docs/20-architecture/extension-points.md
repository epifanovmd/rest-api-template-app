# Точки расширения ядра

Ядро не импортирует модули. Модуль расширяет платформу, регистрируя реализацию
контракта под токеном-реестром (провайдер по токену — [di](di.md)); потребитель
реестра о конкретных модулях не знает.

## Реестры

| Реестр                               | Что добавляет модуль                                      | Потребитель                 |
| ------------------------------------ | --------------------------------------------------------- | --------------------------- |
| схемы аутентификации                 | новый способ аутентификации для декоратора безопасности   | аутентификация маршрутов    |
| обработчики задач                    | очередь с политикой повторов и расписанием                | очередь задач               |
| обработчики HTTP со своим протоколом | маршруты, читающие тело сами, до разбора тела и лимитов   | composition root            |
| провайдеры комнат                    | комнаты, в которые соединение входит само при подключении | транспорт реального времени |
| политики комнат                      | право войти в комнату по запросу клиента                  | транспорт реального времени |
| провайдеры маршрутов                 | маршруты вне генератора (потоковая раздача файлов)        | composition root            |
| индикаторы здоровья                  | проверка своей зависимости в диагностике здоровья         | системные маршруты          |
| политики пароля                      | дополнительные правила пароля                             | модуль-владелец пароля      |
| пробы использования файла            | запрет удалить файл, на который ссылается домен           | модуль файлов               |
| реестр прав                          | права модуля (с областью — и `:own`); засев собирает все  | модуль ролей                |
| обработчики и слушатели событий      | входящие события клиента и доставка доменных событий      | транспорт реального времени |
| связи пользователей                  | кто кому «контакт» и кому видно присутствие               | модуль профиля              |

Реализации одного реестра взаимозаменяемы для инфраструктуры, которая их собирает:
если реализация «не поддерживает» метод контракта, контракт выбран неверно.
Контракты с разными потребителями и временем вызова — разные интерфейсы (например,
обработчик соединения и слушатель событий), а не один «участник» подсистемы.

## Расширение типов

Контракты, которые модуль дополняет типами, а не реализацией, расширяются
дополнением интерфейса (`declare module`) в файле модуля-владельца: карта событий
реального времени, данные шаблонов писем. Общий файл контракта при добавлении или
удалении модуля не правится.

## Новая точка расширения

Появляется как токен и интерфейс в модуле-потребителе (или в ядре, если потребитель —
ядро), а не как импорт конкретного модуля. Реестр вводится, когда варианты уже есть и
меняются независимо; пока их мало и они меняются вместе, обычный `switch` проще
([solid-patterns](../40-principles/solid-patterns.md)).
