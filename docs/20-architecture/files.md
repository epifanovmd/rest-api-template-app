# Хранилище файлов

- Модули работают с абстракцией хранилища по **ключам**; раскладку ключей определяет
  модуль-владелец, пути и адреса хранилища наружу не выходят. Драйверы — локальный
  диск (разработка, один хост) и S3-совместимое хранилище; выбор — конфигурацией.
- Клиент получает только **подписанные ссылки** с ограниченным сроком: для диска —
  подпись приложения и маршрут раздачи с поддержкой диапазонов и кэширования, для
  S3 — presigned-ссылки самого хранилища с публичным адресом, отличным от
  внутреннего. Подпись асинхронна, поэтому DTO с файлами собираются из заранее
  подписанной пачкой карты ссылок; синхронной подписи в DTO нет.
- **Загрузка:** небольшие файлы — multipart через API с проверкой расширения, типа и
  сигнатуры; крупные — напрямую в хранилище по подписанной ссылке на запись с точным
  размером и типом, затем подтверждение, которое проверяет объект и запускает
  обработку.
- **Обработка медиа** (конвертация, превью, метаданные) — фоновой задачей на
  воркере; до её завершения файл доступен в исходном виде. Незавершённые загрузки
  удаляются периодической задачей.
- Удаление файла, на который ссылается домен, запрещено (409) — модули сообщают об
  использовании через пробу ([extension-points](extension-points.md)).
- В БД хранятся только ключ объекта и метаданные ([data](data.md)).

Правила кода для работы с файлами — [conventions/files](../30-conventions/files.md).
