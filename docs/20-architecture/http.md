# HTTP-слой, контракт ошибок и пагинация

## HTTP-слой

- **Маршруты генерируются** из декораторов контроллеров вместе с OpenAPI-спецификацией.
  Сгенерированный файл маршрутов и спецификация не редактируются вручную,
  пересобираются при каждом запуске в разработке и при сборке, коммитятся актуальными.
- **Версия API** — в пути: все маршруты модулей живут под `/api/v<N>/`. Несовместимое
  изменение контракта — новая версия, а не правка существующей.
- **Middleware** — сквозная обработка каждого запроса в фиксированном порядке:
  метрики → идентификатор запроса → логирование → перехват ошибок → системные
  маршруты → заголовки безопасности → CORS → ограничение частоты → разбор тела.
  Перехват ошибок стоит выше всех обработчиков, которые могут бросить.
- **Guards** — точечная защита конкретного маршрута (частота на эндпоинт, требование
  подтверждённого email, HTTPS, whitelist адресов). Guard объявляется декоратором на
  методе и не является заменой аутентификации. Guard с параметрами и состоянием —
  фабрика. Выбор между middleware и guard —
  [placement](placement.md#middleware-или-guard).
- **Аутентификация** — реестр схем безопасности: по имени схемы из декоратора и списку
  scopes схема возвращает контекст вызывающего или отклоняет запрос. Контекст кладётся
  в запрос и извлекается в контроллере единственным хелпером. Модель доступа —
  [access](access.md).
- **Маршруты вне генератора** (потоковая раздача, подписанные загрузки) регистрирует
  модуль через провайдер маршрутов; они не попадают в спецификацию и описываются в
  README модуля.

## Контракт ошибок

Любой ответ со статусом ≥ 400 имеет одну форму: `status`, машинный `code`,
человекочитаемый `message`, необязательные `details` и `requestId`. Стек — только вне
production.

- **Код стабилен** — на него опирается клиент; это часть контракта и не
  переименовывается без новой версии API. Доменная ошибка имеет код
  `<ПРЕФИКС_МОДУЛЯ>_<КЛЮЧ>`, объявленный в модуле; ошибка без доменного кода получает
  код по статусу (`NOT_FOUND`, `CONFLICT`, `INTERNAL_ERROR`).
- **Валидация** — единообразно для генератора маршрутов и схем: 400
  `VALIDATION_ERROR`, `details` — «поле → сообщение».
- **Статусы:** нет прав — 403, не найдено или скрыто (вне области пользователя) —
  404, конфликт с текущим состоянием (дубликат, недопустимый переход, объект
  используется) — 409, лимит — 429 с `Retry-After`, недоступная зависимость — 503.
- **5xx** — обобщённое сообщение наружу, подробный лог и отправка в трекер ошибок;
  внутренний текст и SQL не утекают. Ошибка формата значения в БД — 400.
- Контракт ошибки объявлен на каждом контроллере как ответ по умолчанию и попадает в
  спецификацию. Сообщения — на языке пользователя API, без внутренних деталей.

Как ошибки возникают и обрабатываются в коде — [errors](errors.md).

## Пагинация

- **Список** с известным общим числом — страница по смещению: `items`, `total`,
  `offset`, `limit`. Лимит нормализуется единым хелпером и ограничен сверху; список
  без лимита запрещён.
- **Лента**, в которую записи добавляются во время чтения, — страница по курсору:
  `items` и непрозрачный `nextCursor` (`null` — конец). Курсор строится по
  монотонному ключу с тай-брейком по идентификатору.
- Собственные формы списков не вводятся.

Типы и хелперы страниц — [conventions/dto-validation](../30-conventions/dto-validation.md#пагинация).
