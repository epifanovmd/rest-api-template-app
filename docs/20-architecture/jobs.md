# Задачи и воркеры

Фоновая работа — только через очередь задач на основной БД. Задачи переживают
рестарт, выполняются с повторами на процессах-воркерах
([lifecycle](lifecycle.md#роли-процесса)), а их постановка может быть атомарна с
изменением данных.

- **Обработчик** реализует контракт обработчика и регистрируется в реестре. Его
  описание задаёт очередь (`домен.действие`), число повторов, задержку и
  экспоненциальный рост, срок выполнения, параллельность и расписание. Политика
  применяется к очереди при каждом старте.
- **Постановка** — через абстракцию очереди: отложенный запуск, дедупликация по
  ключу, приоритет, транзакция (outbox).
- **Ошибка** задачи с признаком «без повторов» завершает её сразу; остальные
  повторяются по политике очереди ([errors](errors.md#задачи-и-события)).
- **Периодические задачи** объявляются расписанием в описании обработчика и
  выполняются ровно одним процессом кластера; расписание, удалённое из кода,
  снимается. Таймеры в процессе и ручные блокировки для периодической работы не
  используются.
- **Корреляция:** каждая задача выполняется с собственным идентификатором запроса,
  попадающим во все её логи и метрики.

Когда работа должна быть задачей, а не событием или вызовом, —
[placement](placement.md#событие-задача-или-прямой-вызов). Оформление обработчика —
[conventions/jobs](../30-conventions/jobs.md).
