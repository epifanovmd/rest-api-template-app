# События, слушатели и обработчики

Событийная модель — [architecture/events-realtime](../20-architecture/events-realtime.md).

## Доменные события

- Событие — класс с `readonly`-полями в конструкторе; одно событие — один файл в
  `events/`.
- Событие несёт DTO или идентификаторы. Сущности ORM в событие не попадают.

## Слушатели

- Слушатель подписывается в `register()` и не содержит бизнес-логики: маппинг события
  в отправку, постановку задачи или вызов сервиса.
- Подписка снимается при остановке ([lifecycle](../20-architecture/lifecycle.md#остановка)).

## Реальное время

- Входящее событие реального времени подписывается только через валидирующую обёртку
  (`onValidated`) со схемой и лимитом частоты; голая подписка не используется.
  Ошибка возвращается клиенту подтверждением с машинным кодом, а не роняет
  соединение.
- Новое событие реального времени сначала добавляется в типизированную карту, затем
  используется.
- Изменение сущности с владельцем уходит в комнату списка (держателям права на все)
  и лично владельцу и создателю с областью «свои» — через `OwnedEntityEmitter`. При
  смене владельца бывшему отправляется снятие сущности, его комнаты пересматриваются.
