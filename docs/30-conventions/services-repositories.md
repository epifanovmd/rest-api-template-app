# Сервисы и репозитории

Граница между ними — [module-layers](../20-architecture/module-layers.md#сервис-или-репозиторий).

## Сервис

- Проверяет права и инварианты и бросает доменные ошибки модуля.
- Несколько записей за операцию — транзакция; внутри — репозитории менеджера
  транзакции; задачи — в той же транзакции; события — после фиксации
  ([data](../20-architecture/data.md#транзакции-и-согласованность)).
- Возвращает DTO, а не сущность. Исключение — внутренние методы, которые вызываются
  только другими сервисами того же модуля и не выходят наружу.
- Не знает о HTTP-контексте, транспорте реального времени и заголовках.
- Побочные эффекты за пределами модуля — через событие; долгие и ненадёжные — через
  задачу.
- Одно правило доступа не копируется в несколько сервисов; два похожих метода
  репозитория в разных модулях — нормально.

## Доступ к сущности с владельцем

- Доступ — через `OwnedAccess` модуля (`<feature>.access.ts`: поля владельца и, если
  есть, создателя): `can` — для конкретной сущности, `filter`/`listFilter` —
  ограничение выборки. Ручные сравнения с владельцем и проверки суперпользователя не
  пишутся.
- Действие над сущностью: сначала видимость (право просмотра в области), затем право
  на действие — невидимая сущность — 404, видимая без права — 403.
- Дочерняя сущность ищется только в видимом родителе.

## Репозиторий

- Расширяет базовый репозиторий и помечен декоратором репозитория с сущностью.
- Методы — только запросы и сохранение; без проверок прав и без исключений
  бизнес-уровня. Ограничение области («все / только свои») приходит от сервиса
  готовым параметром выборки; репозиторий его только применяет.
- Условия, связи и сортировки живут в методах репозитория, а не в сервисе.
- Атомарный переход состояния — условный `UPDATE` с возвратом числа затронутых строк;
  решение по результату принимает сервис.
- Общие для многих сущностей операции — в базовом репозитории `core`, а не
  копируются.
