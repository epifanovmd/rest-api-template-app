# Тесты

## Юнит-тесты

- Тест лежит рядом с кодом: `<file>.test.ts`.
- Тест проверяет наблюдаемое поведение сервиса, схемы или хелпера, а не внутреннюю
  реализацию.
- Исправление дефекта начинается с теста, падающего на текущем коде
  ([process/bugfix](../10-process/bugfix.md)); тест остаётся в кодовой базе.
- Зависимости сервиса подменяются фабриками моков из общей тестовой инфраструктуры;
  ad-hoc моки — только для того, чего в ней нет.
- Юнит-тесты не ходят в реальную БД и сеть. Тест с настоящей зависимостью
  пропускается, если её адрес не задан переменной окружения.
- Тесты не зависят от порядка запуска и очищают изменённое глобальное состояние.
- Сгенерированный код и сущности ORM напрямую не тестируются.
- Новая логика сервиса и схемы покрывается юнит-тестами.

## Интеграционный набор (e2e)

- Запускает настоящий сервер против отдельных БД, Redis, SMTP и S3-совместимого
  хранилища и проверяет сценарии по HTTP и сокетам.
- Стенд пересоздаёт только явно тестовые базы.
- Каждый новый эндпоинт покрывается сценарием: последний тест набора падает, если
  эндпоинт спецификации не вызван.
- Набор обязателен перед merge при изменении API, схемы или инфраструктуры; CI
  гоняет его для каждого драйвера хранилища.

Команды запуска — [ops/commands](../70-ops/commands.md).
