# Взаимно вложенные DTO двух модулей

## Ситуация

`user/dto/user.dto.ts` вкладывает `ProfileDto`, а `profile/dto/profile.dto.ts` —
`UserDto`. Импорт через `index.ts` соседа тянет контроллеры и сервисы в цикл, и сервер
не стартует (`Cannot access 'ProfileController' before initialization`; юнит-тесты
этого не ловят, ловит e2e). Сейчас оба импорта идут в папку `dto/` соседа и стоят в
известных исключениях стража `src/modules/module-boundaries.test.ts`.

## Предложение

В `dependencies.md`, раздел «Public API модуля», добавить пункт:

> Папка `dto/` модуля — вторая публичная точка: чужой модуль может импортировать
> `<модуль>/dto`, если DTO двух модулей вкладывают друг друга. `dto/` не импортирует
> сервисы, репозитории и контроллеры своего модуля.

И разрешить `<модуль>/dto` в страже вместо поимённых исключений.

## Обоснование

Вложенные DTO между связанными сущностями — обычный случай, он повторится. Папка
`dto/` — лист графа загрузки, через неё цикла нет. Альтернатива — описывать вложенные
DTO в одном модуле-владельце — дробит контракт ответа между модулями.
