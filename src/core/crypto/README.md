# crypto

Шифрование секретов (токены интеграций, ключи внешних сервисов), которые нужно
хранить в БД и потом читать в открытом виде. Для паролей и токенов, которые
достаточно сверять, — хеши из `core/auth`, не это.

## Public API

| Экспорт             | Что                                                              |
| ------------------- | ---------------------------------------------------------------- |
| `parseSecretBoxKey` | ключ из строки: ровно 32 байта, hex (64 символа) или base64      |
| `sealSecret`        | зашифровать: AES-256-GCM, результат `v1:<base64(iv\|tag\|data)>` |
| `openSecret`        | расшифровать; порча данных или чужой ключ — исключение           |

## Устройство

- IV — 12 случайных байт на каждое шифрование: один и тот же секрет даёт разные
  шифртексты. Тег GCM проверяет целостность.
- Префикс версии `v1` оставляет место для смены алгоритма без миграции старых записей.
- Ключ хранит модуль-потребитель (своя переменная окружения в конфиге модуля),
  парсит его один раз при старте через `parseSecretBoxKey`.

## Зависимости

Только `crypto` Node.js. В шаблоне пока не используется — заготовка для модулей.

## Gotcha

- Смена ключа делает все сохранённые секреты нечитаемыми: ротация — только
  перешифрованием данных.
- Ошибки — обычный `Error`, не `HttpException`: вызывающий переводит их в доменную ошибку.
