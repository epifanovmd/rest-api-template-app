# event-bus

Шина событий внутри процесса. Модули публикуют события-классы, другие модули
подписываются в своих listener-ах — без прямых зависимостей между сервисами.

## Public API

| Экспорт    | Что                                                                   |
| ---------- | --------------------------------------------------------------------- |
| `EventBus` | `emit`, `emitAsync`, `on` (→ функция отписки), `once`, `off`, `clear` |

## Устройство

- Ключ подписки — **конструктор** события (`event.constructor`), не строка: имя класса
  при минификации не важно, наследник — отдельный тип события.
- `emit` — синхронный вызов обработчиков; исключения и отклонённые промисы
  логируются, до вызывающего не доходят.
- `emitAsync` — ждёт все обработчики (`Promise.allSettled`), ошибки тоже только в
  лог. Для случаев, когда вызывающему нужно дождаться реакции (например, отзыв токенов
  перед ответом).
- Регистрируется в `CoreModule` (singleton); `App` вызывает `clear()` при остановке.

## Зависимости

`core/decorators`, `core/logger`. Используют почти все модули (api-key, audit, auth,
biometric, file, passkeys, profile, role, session, socket, user) и `src/app.ts`.

## Gotcha

- Шина только внутри процесса: событие, опубликованное на api-процессе, не дойдёт до
  слушателей воркера. Межпроцессное — Redis-адаптер Socket.IO, очередь задач или
  `PgSignals`.
- Событие публикуется после коммита транзакции, иначе слушатель увидит данные,
  которых ещё (или уже) нет.
- Ошибка обработчика не откатывает действие — критичную реакцию делать задачей очереди.
